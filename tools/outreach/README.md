# Инструмент холодной рассылки — архбюро и дизайн-студии

Набор Node-скриптов, который: (1) находит потенциальных клиентов студии
«Нейро Отличник» — архитектурные бюро и дизайн-студии — с контактными
email, и (2) готовит и рассылает им уникальные письма с коммерческим
предложением. Все шаги отдельные и запускаются вручную по очереди — так
проще проверять результат на каждом этапе и не разослать письма раньше,
чем вы на них посмотрели.

Ориентировано на сегмент №1 из брендбука «Нейро Отличник» (`Архитектурные
бюро и дизайн-студии`, приоритет «высокий») — оффер, аргументы и тон
письма в `brand.json`/`lib/templates.js` собраны из брендбука `V.1 · 2026`.

## Честно про место email в привлечении клиентов

Сам брендбук для этого сегмента приоритетными каналами называет
**Telegram-чаты архитекторов, Revit/ArchiCAD-сообщества и сарафан**, а не
email. Это не повод не делать рассылку, но повод не ждать от неё
основного потока клиентов:

- Реалистичный ответ на холодный B2B email в незнакомой нише — 1–5%.
  Email здесь — это охват «длинного хвоста» бюро, до которых руки не
  доходят вручную, а не замена личного присутствия в профильных чатах.
- Аудитория узкая и доверительная — испорченная спамом репутация бьёт
  как раз по тому каналу (сарафан/сообщества), который важнее email.
  Поэтому в инструменте намеренно нет режима «разослать всем разом»:
  только маленькие пачки, подтверждение перед отправкой и лимиты.
- Лучший результат — комбинация: эта рассылка на компании, до которых
  не добраться лично, + ручное присутствие в Telegram-чатах архитекторов
  и сарафан на реальных проектах.

## Пайплайн

```
discover-2gis.js  ─┐
discover-yandex.js ─┼──▶ data/leads.csv ──▶ enrich-emails.js ──▶ data/leads.csv (+email)
                    │                                                    │
                    └── можно запускать оба, лиды объединятся ──────────┘
                                                                          ▼
                                                            generate-drafts.js
                                                                          │
                                                                          ▼
                                                        data/drafts/*.json + drafts_index.csv
                                                                          │
                                                     (посмотрите глазами!)│
                                                                          ▼
                                                     send-emails.js --dry-run  (по умолчанию)
                                                     send-emails.js --send     (реальная отправка)
```

Каждый шаг можно вызывать вручную из консоли (см. ниже) — либо всё сразу
через кнопки Telegram-бота (`bot.js`, шаг 5), включая отчёт после
отправки. `status.js` в любой момент показывает срез всей воронки, ничего
не запуская.

Все промежуточные данные (`data/`) и креды (`.env`, `config.json`) — в
`.gitignore`, в репозиторий не попадают: там живут email и другие контакты
реальных компаний, это не то, что должно лежать в публичном коде игры.

## Установка

Зависимости уже добавлены в корневой `package.json` (`cheerio`,
`nodemailer`, `csv-parse`, `csv-stringify`) — если ставите с нуля:

```bash
npm install
cp tools/outreach/.env.example tools/outreach/.env
# и заполните tools/outreach/.env своими ключами/SMTP-данными
```

## Шаг 1. Найти компании — discover-2gis.js / discover-yandex.js

Нужен бесплатный API-ключ хотя бы одного источника:

- **2GIS Catalog API** — https://dev.2gis.ru/ (раздел Places/Каталог). Даёт
  название, адрес, сайт, телефон и **иногда email прямо из карточки**.
- **Yandex Geosearch API** (продукт «Search API» / Геосправочник) —
  оформляется в https://developer.tech.yandex.ru/services. Даёт название,
  адрес, сайт, телефон, но **email не даёт** — его находит следующий шаг.

Оба источника не привязаны к произвольному «городу» напрямую — под
капотом это поиск по точке (долгота/широта) + радиус. Крупные российские
города уже зашиты в `lib/cities.js`; свой город — через `config.json`
(см. `config.example.json`) или флаг `--cities`.

```bash
# создать config.json (необязательно, но удобно для своих городов/категорий)
cp tools/outreach/config.example.json tools/outreach/config.json

npm run leads:2gis -- --cities "Москва,Санкт-Петербург,Казань"
npm run leads:yandex -- --cities "Москва,Санкт-Петербург,Казань"
```

Оба скрипта дописывают (не перетирают) `data/leads.csv` — можно
запускать их оба, гонять по частям городов, повторять на следующий день
за новыми: дубли по домену/названию+городу схлопываются автоматически.

> Эндпоинты и параметры этих API документированы у самих 2GIS/Yandex и
> иногда меняются — если запрос вернул ошибку формата, сверьтесь с
> актуальной документацией (ссылки — в шапке каждого скрипта).

## Шаг 2. Найти недостающие email — enrich-emails.js

```bash
npm run leads:enrich -- --limit 50   # сначала на пробе 50 лидов
npm run leads:enrich                 # затем на всех остальных
```

Заходит на сайт каждой компании (главная + `/contacts`, `/kontakty`,
`/about` и т.п.), ищет email в HTML. Уважает `robots.txt` и делает паузу
между запросами к одному домену — прогон на сотни лидов **небыстрый**,
это осознанный компромисс, чтобы не быть навязчивым ботом для чужих
сайтов. Заодно сохраняет текст главной страницы в `data/site_snippets/` —
по нему следующий шаг подбирает релевантный «крючок» в письме.

## Шаг 3. Собрать уникальные письма — generate-drafts.js

```bash
npm run leads:draft
```

Каждое письмо собирается из независимо выбираемых блоков (тема,
вступление, «крючок» под специализацию компании, аргументы, призыв к
действию) — выбор детерминирован по хэшу от компании, то есть при
повторном запуске письма не меняются, но у разных компаний получаются
разные формулировки, а не один текст с подставленным именем. «Крючок»
берётся из `data/site_snippets/*.txt`: если на сайте компании
встречаются слова вроде «жк», «тендер», «bim», «фасад» — письмо
упоминает именно этот кейс, а не общий питч.

**Обязательно посмотрите `data/drafts_index.csv` и хотя бы часть файлов
в `data/drafts/*.json` глазами перед отправкой.** Тексты и факты в
`brand.json`/`lib/templates.js` — свободно правьте под себя.

## Шаг 4. Отправить — send-emails.js

```bash
npm run leads:send -- --dry-run          # по умолчанию и так dry-run — просто убедиться
npm run leads:send -- --send --limit 20  # реальная отправка, первые 20
```

- **По умолчанию — dry-run**, ничего не отправляется, пока явно не
  указан `--send`.
- `data/ledger.json` помнит, кому уже отправлено — повторный запуск не
  продублирует письма.
- `data/suppressed.txt` — список адресов, кому писать нельзя (отписки,
  отбитые письма); добавляйте туда вручную по одному email на строку
  или через код (`lib/store.js#addSuppressed`).
- `--limit` (по умолчанию 30) и `--delay-ms` (по умолчанию 8000) — чтобы
  не отправлять залпом с одного личного почтового ящика: это первое, что
  роняет репутацию отправителя и уводит все письма в спам.
- `--daily-cap` (по умолчанию 80) — суммарный лимит на сутки поверх
  `--limit`, считается по `data/ledger.json`.

### Прогрев: с чего начать объём

Новый (или ранее не рассылавший) почтовый ящик/домен нужно разгонять
постепенно — иначе первые же сотни писем улетят в спам, и это испортит
репутацию не только рассылке, но и обычной деловой переписке с того же
адреса:

| Неделя | Писем в день |
|---|---|
| 1–2 | 10–15 |
| 3–4 | 20–30 |
| 5+  | 40–80 (значение `--daily-cap` по умолчанию) |

Смотрите на процент ошибок/отказов в `data/ledger.json` (`status:
"failed"`) и на статус в `node tools/outreach/status.js` — если ошибок
много, снижайте объём, а не увеличивайте.

## Шаг 5. Управление с телефона — bot.js

Telegram-бот поверх всего пайплайна — раз Telegram и так основной канал
студии, это удобнее, чем консоль. Работает через long polling, поэтому
не нужен ни публичный HTTPS, ни отдельный домен — только всегда включённая
машина с интернетом (см. «Где это должно работать» ниже).

**Настройка:**
1. Создайте бота через [@BotFather](https://t.me/BotFather) (`/newbot`),
   получите токен → `TELEGRAM_BOT_TOKEN` в `.env`.
2. Узнайте свой числовой Telegram ID, например через
   [@userinfobot](https://t.me/userinfobot) → `TELEGRAM_ALLOWED_USER_IDS`
   в `.env` (через запятую, если пользователей несколько).
   **Без этого бот не ответит вообще никому** — это единственная защита
   от того, что кто-то посторонний начнёт слать письма от вашего имени.
3. `npm run leads:bot` (или через pm2/systemd — см. ниже).

**Меню в Telegram:**

- **📊 Статус** — сколько лидов найдено, у скольких есть email, сколько
  черновиков готово, сколько писем отправлено сегодня/всего, сколько
  ошибок и отписавшихся. Ничего не отправляет, безопасно тыкать когда угодно.
- **🔎 Найти лидов** / **📧 Найти email** / **📝 Собрать черновики** — то
  же самое, что шаги 1–3 из консоли, но с укороченными лимитами
  (`BOT_ENRICH_LIMIT`, `BOT_DISCOVER_MAX_PAGES`), чтобы бот не завис
  надолго на одном тапе.
- **✉️ Отправить** — сначала считает и показывает **точное число писем**,
  которые сейчас уйдут, и только после кнопки-подтверждения `✅ Отправить
  N` реально их отправляет. Вне рабочих часов (`BUSINESS_HOURS_*` в
  `.env`) добавляет предупреждение, но не блокирует — решение всегда за
  вами. По завершении присылает тот же отчёт, что и консольный
  `send-emails.js`: кому ушло, кому нет и почему.

Это и есть «зашёл с телефона, нажал кнопку, получил отчёт»: два тапа
(«Отправить» → «Подтвердить N») вместо одного — намеренно, чтобы случайное
нажатие не разослало письма, которые потом не отозвать.

**Где это должно работать.** Боту нужен процесс, который работает
круглосуточно — не сам телефон. Варианты:
- дешёвый VPS (от ~300 ₽/мес у российских хостеров, или DigitalOcean/Hetzner) —
  запустить через `pm2 start tools/outreach/bot.js --name outreach-bot`
  или через systemd-юнит;
- любой уже имеющийся у вас всегда включённый компьютер/сервер.

Сам телефон в этой схеме — просто клиент Telegram, ничего на нём
устанавливать не нужно.

## О соответствии закону и этике холодных рассылок

Это инструмент для B2B-аутрича на публичные бизнес-контакты (`info@`,
`office@`, адреса с страниц «Контакты»), а не для рассылки физлицам без
согласия. Тем не менее:

- В России действует ст. 18 ФЗ «О рекламе» (требует согласия адресата на
  рекламную рассылку) и ФЗ «О персональных данных» — они по-разному
  применяются к «коммерческому предложению по адресу компании» и
  «рекламе физлицу», и однозначного универсального ответа тут нет.
  **Это не юридическая консультация** — если рассылка станет массовой и
  регулярной, стоит свериться с юристом.
- В каждое письмо уже встроена простая возможность отписаться (ответить
  «стоп») и заголовок `List-Unsubscribe` — **обязательно** обрабатывайте
  такие ответы, добавляя адрес в `data/suppressed.txt`.
- Не рассылайте на личные (не рабочие) адреса, найденные на сайте
  случайно — только на явно контактные (`info@`, `contact@`,
  `hello@`, штатный email из карточки на 2GIS/Яндекс).
- `enrich-emails.js` уважает `robots.txt` и не заваливает чужие сайты
  запросами — не убирайте эти проверки.
- Для рассылок на сотни/тысячи адресов в месяц личный SMTP-ящик — плохая
  идея: нет прогрева домена, репутации IP, статистики открытий, обработки
  отказов. Тогда лучше подключить транзакционный/рассылочный сервис
  (Unisender, SendPulse, Mailgun, Postmark и т.п.) — `send-emails.js`
  можно переписать под их API, сохранив логику ledger/suppression как
  есть.
- **Отправляйте с отдельного поддомена**, а не с `neurootlichnik.ru`
  напрямую (например, заведите `send.neurootlichnik.ru` или
  `hello@send.neurootlichnik.ru` и настройте под него SPF/DKIM). Если
  рассылка всё же словит жалобы и репутационный удар, под раздачу попадёт
  только этот поддомен — основной домен и обычная деловая почта
  (`info@neurootlichnik.ru`) не пострадают.

## Файлы и структура

```
tools/outreach/
  brand.json              — факты из брендбука (оффер, цены, портфолио, тон голоса)
  lib/
    env.js                — загрузчик .env без внешней зависимости
    cli.js                — парсер флагов командной строки
    http.js                — вежливый fetch: robots.txt, задержки, таймауты
    cities.js              — координаты городов для 2GIS/Yandex API
    emails.js              — извлечение email/текста из HTML (чистые функции)
    hash.js                 — детерминированный выбор варианта письма
    templates.js            — варианты письма (тема/вступление/крючок/CTA)
    store.js                 — чтение/запись leads.csv, ledger, suppression list
    status.js                — сводный отчёт по воронке (использует и status.js, и bot.js)
    telegram.js              — минимальный клиент Telegram Bot API (long polling)
    run-script.js            — запуск CLI-скриптов из бота как дочерних процессов
  discover-2gis.js         — поиск компаний через 2GIS Catalog API
  discover-yandex.js       — поиск компаний через Yandex Geosearch API
  enrich-emails.js         — обход сайтов компаний в поисках email
  generate-drafts.js       — сборка уникальных писем
  send-emails.js           — отправка через SMTP (nodemailer)
  status.js                — печатает сводку по воронке (CLI-версия lib/status.js)
  bot.js                   — Telegram-бот: управление всем пайплайном с телефона
  config.example.json      — пример config.json (свои города/категории)
  .env.example              — пример .env (API-ключи, SMTP, токен бота)
  data/ (gitignore)          — leads.csv, drafts/, site_snippets/, ledger.json, suppressed.txt
```
